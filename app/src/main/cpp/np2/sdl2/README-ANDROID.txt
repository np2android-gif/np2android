sdl2/ (画面の表示)
==================

xnp2 の sdl2 をもとにしている。ここでは画面の表示について Android 向けに変えたところを書く。
変更箇所には /* ANDROID-SCRN */ の印を付けている (タッチの換算は port/taskmng.c、縦画面の配置は
Kotlin の Np2Activity.kt にも同じ印がある)。

640x480 のゲスト画面
  xnp2 本体 (vram/dispsync.c) は 480 ラインまで描けるが、sdl2 の描画面は 640x400 で作られ、
  scrnmng_surflock() で高さを 400 に切っていた。Windows 2000 のセットアップは 640x480 で描くので、
  下の 80 ライン (キーの案内の行など) が見えなかった。
  - np2.h の FULLSCREEN_HEIGHT を 480 にし、描画面とテクスチャを 640x480 で作る。
  - 画面に出す高さ (s_disph) は、dispsync.c が scrnmng_setheight() で知らせる高さ
    (dsync.scrnymax) が 400 より大きいときだけ 480、それ以外は 400。
  - 画面に出す処理は present() にまとめた。描画面のうち 640 x s_disph の分だけを出す。
  - 縦画面 (ウィンドウが 640x480 の比より縦長) では、SDL の論理サイズを常に 640x480 にし、絵を
    上に寄せる。400 ラインのときは下に 80 ライン分の黒い帯が出るが、絵の大きさと上端は 480 ライン
    のときと変わらず、ソフトキーボードも動かない。Kotlin 側 (Np2Activity.placePortrait) が縦画面の
    枠を常に 4:3 (幅 x 3/4) にしている。
  - 横画面 (横長) では、SDL の論理サイズを画面に出す高さ (640x400 か 640x480) に合わせ、
    縦横比を保って高さいっぱいに出す。
  - 内蔵メニュー (np2 のメニュー) は、開いたときの高さ (s_disph) で作る。開いている間は高さを
    変えない。下の帯をタップすると、メニューの外をタップしたときと同じ扱いになる。
  - タッチの移動量の換算 (port/taskmng.c の touch_topc98) は、scrnmng_getdispheight() で表示中の
    高さを使う。縦画面ではどちらの高さでも倍率は「幅 / 640」になる。下の帯も絵の上と同じタッチ
    パッドとして働く。
  - 400 ラインのときの見た目は 0.86-a10 と同じ (縦画面では下に帯が出る分、ソフトキーボードが
    約 9% 低くなった)。拡大は整数倍ではない (XZ3 では 2.25 倍) ので、描画面の大きさを変えたことで
    画素の丸めがところどころ 1 行ずれるが、絵の内容は変わらない。
  - ideio などの構造体やステートセーブの形式は変えていない。
